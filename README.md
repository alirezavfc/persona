# Persona

Persona is a minimal, privacy-focused, text-based social network inspired by Twitter/X.

Instead of traditional names and usernames, users are identified by a unique **Persona ID**, automatically generated by the system (e.g. `persona0`).

Persona aims to provide a simple user experience while being built on a solid software engineering foundation, with a focus on security, privacy, maintainability, and real-world architecture.

## Core Features

### Accounts & Authentication

- User registration with a password
- Automatically generated Persona ID
- Automatically generated Recovery Key
- Login using Persona ID and password
- Account recovery using Recovery Key
- Password change
- Recovery Key regeneration
- Secure session management

Users are not required to provide an email address, phone number, real name, or other personal information.

### User Profiles

Each user has a public profile containing:

- Persona ID
- Predefined avatar
- Follower count
- Following count
- Posts and replies in a single chronological list

Users can:

- Follow and unfollow other users
- Block other users
- Change their avatar
- Change their password
- Regenerate their Recovery Key

There are no private profiles.

### Posts

- Text-only posts
- Maximum length: **400 characters**
- Create posts directly from the user's profile
- Display posts and replies in the same chronological list

Posts cannot be edited or deleted after publishing.

### Blocking

Blocking permanently separates two users.

After blocking:

- Neither user can view the other's profile or content.
- Both users are removed from each other's follow relationships.
- Neither user can follow or interact with the other.
- Neither user can unblock the other.
- The blocked relationship is permanent through the normal user interface.

A clear warning will be displayed before confirming this irreversible action.

## Development Approach

Persona is developed incrementally.

The development process follows:

1. Define requirements.
2. Identify system responsibilities.
3. Make architectural decisions.
4. Implement a small feature.
5. Test and review.
6. Refine the implementation.

The goal is to understand and build a realistic application without unnecessary complexity or premature architecture.

## Project Status

**Current focus: Account Authentication and User Profiles.**

The first implementation phase focuses on:

- User registration and login
- Persona ID and Recovery Key generation
- Account recovery
- User profile functionality
- Avatar selection and editing
- Follow and block functionality
- Creating and displaying posts on user profiles

After completing this phase, development will move toward the Home Feed and broader social features.

Persona is an evolving project. Its requirements and architecture may change as implementation reveals new constraints and opportunities.
